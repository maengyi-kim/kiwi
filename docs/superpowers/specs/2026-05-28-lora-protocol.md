# 厂区监控系统 — LoRa 通信协议规范 v1.1

> 文档状态：草案
> 更新日期：2026-05-29
> 上一版本：v1.0 (2026-05-28)
>
> v1.1 变更摘要：
> - 吸收 LoRaWAN 精华：ADR 自适应速率、OTAA 入网、Confirmed/Unconfirmed、帧计数器防重放、MAC 命令搭车、跳频、占空比、LinkCheck
> - 帧头重构：新增 Confirmed 标志位和帧计数器
> - 消息类型压缩为 5bit（32 种），按类别重新分配

## 一、设计原则

1. **帧结构统一**：所有消息共用一种帧格式，靠"消息类型"区分
2. **载荷自描述**：载荷内用 TLV（Type-Length-Value），解析方能理解未知字段
3. **版本内置**：协议版本在帧头，升级协议不升级硬件可回退
4. **双向平等**：上下行用同一帧格式，不做不对称设计
5. **安全分层**：加密/签名在载荷之上附加，不影响帧结构本身
6. **吸收 LoRaWAN 精华**：ADR、OTAA、帧计数器、MAC 搭车——工业验证的最佳实践

## 二、通用帧格式 (v1.1)

```
Byte:   0        1        2        3        4        5        6       7..N     N+1  N+2
     ┌────────┬────────┬────────┬────────┬────────┬────────┬────────┬─────────┬──────┬──────┐
     │版本2bit│目标ID │目标ID  │源ID   │源ID   │帧计数器│载荷长度│  载荷    │      │      │
     │Conf 1b│ 高字节 │低字节  │高字节 │低字节 │  1B    │  1B    │ 0-255B  │      │      │
     │类型5bit│        │        │       │       │        │        │         │      │      │
     └────────┴────────┴────────┴───────┴───────┴────────┴────────┴─────────┴──────┴──────┘
      Byte0   Byte1    Byte2   Byte3    Byte4   Byte5    Byte6    Byte7..N  N+1..N+2

                                          ┌──────┐
                                          │CRC16 │
                                          │ 2B   │
                                          └──────┘
```

### Byte0 位域分配

```
Bit:   7    6    5    4    3    2    1    0
     ┌────┬────┬────┬──────────────────────┐
     │ Ver│Ver │ C  │    Message Type      │
     │ 1  │ 0  │    │      (5 bits)        │
     └────┴────┴────┴──────────────────────┘
```

| 位域 | 位宽 | 说明 |
|------|------|------|
| Protocol Version | 2bit | 当前 `01`，升级后递增 |
| Confirmed | 1bit | `0`=Unconfirmed（发了不管），`1`=Confirmed（需要 ACK） |
| Message Type | 5bit | 0x00-0x1F (32 种，见第三章) |

### 其他字段

| 字段 | 位宽 | 说明 |
|------|------|------|
| Target ID | 16bit | 目的地址。`0x0000`=广播，`0xFFFF`=网关，其他=节点ID |
| Source ID | 16bit | 发送方地址 |
| Frame Counter | 8bit | **单调递增，重启后从 EEPROM 读取续增**。接收方丢弃 ≤ 上次的帧（防重放） |
| Payload Length | 8bit | 载荷字节数 0-255。0 表示纯信令（如心跳） |
| Payload | 0-255B | 消息内容，格式由消息类型决定 |
| CRC16 | 16bit | CCITT 多项式 0x1021，覆盖 Byte0 到载荷末 |

**头固定 7 字节**（v1.0 为 6 字节），总帧长 9-264 字节。

### Confirmed 标志使用规则

| 消息方向 | 默认 | 示例 |
|----------|------|------|
| 传感器数据上报 | **Unconfirmed (0)** | 丢了等下包，不消耗空时重传 |
| 设备状态上报 | **Unconfirmed (0)** | 同上 |
| 心跳 | **Unconfirmed (0)** | 同上 |
| 下行指令 | **Confirmed (1)** | 必须确认，5秒超时重传，最多3次 |
| 报警/事件日志 | **Confirmed (1)** | 关键告警不能丢 |
| 配置写入 | **Confirmed (1)** | 必须确认生效 |

## 三、消息类型全集 (32种，v1.1)

按 Byte0 低 5bit 分配：

### 3.1 数据类 (0x00-0x07)

| 类型码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x00 | 传感器数据上报 | 上行 | 定时上报，TLV 载荷（见 4.1） |
| 0x01 | 设备状态上报 | 上行 | 电池、信号、运行时间、传感器健康 |
| 0x02 | 事件日志上报 | 上行 | 重启、异常、传感器故障 |
| 0x03 | 批量数据补发 | 上行 | 断网恢复后补发，多条合并 |
| 0x04 | 门禁状态 | 上行 | 门开/关/未关严 |
| 0x05 | 能耗数据 | 上行 | 电流、电压、功率、累计电量 |
| 0x06-0x07 | **保留** | — | |

### 3.2 控制类 (0x08-0x0F)

| 类型码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x08 | 开关控制 | 下行 | 继电器开/关/脉冲 |
| 0x09 | 开关应答 | 上行 | ACK：成功/失败+原因码 |
| 0x0A | PWM/模拟量 | 下行 | 调速、调光、阀门开度 |
| 0x0B | PWM/模拟量应答 | 上行 | ACK |
| 0x0C | 多路联动 | 下行 | 一个指令控制多个输出口 |
| 0x0D | 多路联动应答 | 上行 | ACK |
| 0x0E | 紧急停止 | 下行+广播 | 优先级最高，三连发保证 |
| 0x0F | 紧急停止应答 | 上行 | ACK |

### 3.3 管理类 (0x10-0x17)

| 类型码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x10 | 读取配置 | 下行 | 查询节点当前参数 |
| 0x11 | 读取配置应答 | 上行 | 返回参数列表 |
| 0x12 | 写入配置 | 下行 | 修改上报间隔、告警阈值等 |
| 0x13 | 写入配置应答 | 上行 | ACK，含生效状态 |
| 0x14 | 固件升级通知 | 下行 | 大小、分块数 |
| 0x15 | 固件升级确认 | 上行 | 确认/拒绝 |
| 0x16 | 固件数据块 | 下行 | 含块号、总块数 |
| 0x17 | 固件数据块应答 | 上行 | ACK/重传请求 |

**管理类扩展（使用载荷中的 MAC 命令区分）**：传感器校准、设备重启、声光报警控制等指令通过 MAC 命令搭车发送（见第六章），不占用独立消息类型。

### 3.4 系统类 (0x18-0x1F)

| 类型码 | 名称 | 方向 | 来源 | 说明 |
|--------|------|------|------|------|
| 0x18 | 心跳 | 上行 | — | 空载荷，证明在线 |
| 0x19 | 心跳应答 | 下行 | — | 含服务器时间（校时） |
| 0x1A | 设备入网请求 | 上行 | **LoRaWAN OTAA** | Join-Request: DevEUI + DevNonce |
| 0x1B | 设备入网确认 | 下行 | **LoRaWAN OTAA** | Join-Accept: DevAddr + 密钥材料 |
| 0x1C | LinkADRReq | 下行 | **LoRaWAN ADR** | 自适应速率调整指令 |
| 0x1D | LinkADRAns | 上行 | **LoRaWAN ADR** | 速率调整确认 |
| 0x1E | LinkCheckReq | 上行 | **LoRaWAN** | 链路质量诊断请求 |
| 0x1F | LinkCheckAns | 下行 | **LoRaWAN** | 应答：网关收包数+信号 |

## 四、载荷格式定义

### 4.1 传感器数据 (0x00)

载荷使用精简二进制 TLV（Type-Length-Value）：

```
Type(1B) | Length(1B) | Value(N B) | Type | Length | Value | ...
```

**传感器 Type 编码**（与 v1.0 完全兼容）：

| Type | 名称 | 单位 | Value 编码 |
|------|------|------|------------|
| 0x01 | 温度 | 0.1°C | int16, 小端 (如 -225 = -22.5°C) |
| 0x02 | 湿度 | % | uint8 (0-100) |
| 0x03 | 水位 | mm | uint16, 小端 |
| 0x04 | 大气压 | 0.1 hPa | uint16, 小端 |
| 0x05 | 光照 | lux | uint16, 小端 |
| 0x06 | CO2 | ppm | uint16, 小端 |
| 0x07 | NH3 (氨气) | ppm | uint16, 小端 |
| 0x08 | pH 值 | 0.01 | uint16, 小端 |
| 0x09 | 溶解氧 | 0.01 mg/L | uint16, 小端 |
| 0x0A | 电流 | mA | uint16, 小端 |
| 0x0B | 电压 | mV | uint16, 小端 |
| 0x0C | 功率 | W | uint16, 小端 |
| 0x0D | 累计电量 | Wh | uint32, 小端 |
| 0x0E | 流量 | L/min | uint16, 小端 |
| 0x0F | 门状态 | — | uint8: 0=关, 1=开, 2=未关严, 3=故障 |
| 0x10 | 振动 | — | uint8: 0-255 (归一化) |
| 0x11-0x7F | **保留** | — | |
| 0x80-0xFF | **用户自定义** | — | |

**示例（冷库1号上报温湿度，Unconfirmed）：**

```
帧:
  Byte0: 0x40 (Ver=01, Confirmed=0, Type=0x00 传感器数据)
  Byte1-2: 0x00, 0x01  (Target=网关)
  Byte3-4: 0x00, 0x01  (Source=节点1)
  Byte5: 0x2A           (Frame Counter=42)
  Byte6: 0x07           (Payload Len=7)
  Byte7-13:             (Payload)
    0x01, 0x02, 0x1F, 0xFF   ← Temperature: type=0x01, len=2, val=-225(-22.5°C)
    0x02, 0x01, 0x41         ← Humidity: type=0x02, len=1, val=65(65%)
  Byte14-15: CRC16

共 7(头)+7(载荷)+2(CRC) = 16 字节 → 空中时间约 51ms (SF7) ~ 1.5s (SF12)
```

### 4.2 设备状态 (0x01)

TLV 字段：

| Type | 名称 | 说明 |
|------|------|------|
| 0x20 | 电池电压 | uint16 mV |
| 0x21 | 供电方式 | uint8: 0=电池, 1=外接电源, 2=两者 |
| 0x22 | RSSI | int8 dBm (负数) |
| 0x23 | SNR | int8 dB |
| 0x24 | 运行时间 | uint32 秒 (自上次重启) |
| 0x25 | 固件版本 | uint16: 高字节=主版本, 低字节=次版本 |
| 0x26 | 硬件版本 | uint16 |
| 0x27 | 重启原因 | uint8: 0=上电, 1=软件复位, 2=看门狗, 3=低电压, 4=指令 |
| 0x28 | MCU温度 | int8 °C |
| 0x29 | 空闲堆栈 | uint16 字节 |
| 0x2A | 异常计数 | uint16 |
| 0x2B | 最后错误码 | uint16 (见 4.3) |
| 0x2C | 传感器健康 | bitmap: bit0=DHT22 ok, bit1=超声波 ok, ... |
| 0x2D | LoRa重传次数 | uint16 |

### 4.3 事件日志 (0x02) 与错误码

**事件码：**

| 代码 | 含义 |
|------|------|
| 0x0100 | 设备上电 |
| 0x0101 | 设备软重启 |
| 0x0102 | 看门狗复位 |
| 0x0103 | 进入低功耗模式 |
| 0x0104 | 唤醒 |
| 0x0200 | 传感器连接 |
| 0x0201 | 传感器断开 |
| 0x0202 | 传感器校准完成 |
| 0x0300 | 配置变更 |
| 0x0301 | 固件升级开始 |
| 0x0302 | 固件升级完成 |
| 0x0303 | 固件回退 |
| 0x0400 | 入网成功 |
| 0x0401 | 入网被拒 |
| 0x0402 | 重入网（帧计数器重置） |
| 0x0500 | 收到紧急停止 |
| 0x0501 | 输出状态变更 |
| 0x0600 | 电池电量低警告 |
| 0x0601 | 电池电量极低(即将关机) |
| 0x0700 | LoRa信号弱 (<-120dBm) |

**错误码：** 同 v1.0 附录（0x0000 正常 ~ 0xFFFF 未知错误），此处不重复。

### 4.4 批量数据补发 (0x03)

载荷：1 字节条数(1-255)，后面跟多条传感器数据，每条格式同 4.1。

### 4.5 OTAA 入网载荷

#### 入网请求 (0x1A)

```
载荷：
  DevEUI    8B    设备唯一标识（出厂烧录，IEEE EUI-64）
  DevNonce  2B    随机数，防重放（节点生成，存 EEPROM，每次入网递增）
  JoinEUI   8B    应用标识（= 网关/服务器标识，出厂烧录）
```

#### 入网确认 (0x1B)

```
载荷：
  AppNonce  3B    服务器随机数
  NetID     3B    网络标识
  DevAddr   4B    分配的短地址（此后通信只用 DevAddr）
  DLSettings 1B   bit0-3=RX1数据率偏移, bit4=RX2数据率, bit5-7=TX功率
  RxDelay   1B    RX1窗口延迟（秒）
  CFList    16B   可选信道频率列表
```

#### 密钥派生（STM32 硬件 AES）

```
双方用 AppKey（16B，出厂预烧）派生：

NwkSKey = aes128_encrypt(AppKey, 0x01 | AppNonce | NetID | DevNonce | pad16)
AppSKey = aes128_encrypt(AppKey, 0x02 | AppNonce | NetID | DevNonce | pad16)

用途：
  NwkSKey → 计算/校验 MIC（4字节，帧末尾），保证帧完整性
  AppSKey → 加密/解密载荷（AES-128-CTR，可选）
```

**本期实现**：NwkSKey 用于 MIC 校验（必需），AppSKey 载荷加密暂不启用（预留接口）。

### 4.6 LinkADRReq/Ans (0x1C/0x1D) — 自适应速率

#### LinkADRReq (下行)

```
载荷：
  DataRate  1B    目标数据率 (0=SF12, 1=SF11, ..., 5=SF7)
  TXPower   1B    目标发射功率 dBm (2-20)
  ChMask    2B    信道掩码（16bit，每bit对应一个信道）
  NbTrans   1B    重复次数（默认1）
```

#### LinkADRAns (上行)

```
载荷：
  Status    1B    bit0=DataRate OK, bit1=TXPower OK, bit2=ChMask OK, bit3=NbTrans OK
  若失败：bit7=1，后续字节说明原因
```

#### ADR 触发条件（网关侧）

```
每收到 20 包 → 评估一次，按 RSSI 平均值判断：

  RSSI > -60 dBm  → DR5(SF7),  TX=10dBm  距离近，省电优先
  RSSI -60~-80    → DR3(SF9),  TX=14dBm  均衡
  RSSI -80~-100   → DR1(SF11), TX=17dBm  保连接
  RSSI < -100     → DR0(SF12), TX=20dBm  极限

ADR 降级（快速响应）：
  连续 3 次 Unconfirmed 上报未收到（通过 LinkCheck 得知）
  → 立即下降一级 DataRate，不等 20 包评估周期
```

### 4.7 LinkCheckReq/Ans (0x1E/0x1F) — 链路诊断

#### LinkCheckReq (上行)

```
载荷：空（0字节）
节点定期发送（每 30 次上报附带一次），询问网关收包情况。
```

#### LinkCheckAns (下行)

```
载荷：
  GwCnt    2B    网关最近 48 小时内收到的该节点包数
  Margin   1B    链路余量 dB（最近包 SNR - 解调门限）
```

节点处理逻辑：
```
丢包率 = (本地上行帧计数器增量 - GwCnt) / 上行帧计数器增量
丢包率 > 50% → 触发 ADR 降级请求（上行自带数据速率下调意图）
丢包率 < 10% → 正常
```

## 五、下行指令与 MAC 命令

### 5.1 下行指令（控制/管理类消息）

格式与上行一致（同一帧格式），载荷定义如下。

#### 开关控制 (0x08)

```
载荷：
  port    uint8   输出端口号 (0-7)
  action  uint8   0=关, 1=开, 2=脉冲(200ms), 3=翻转
  delay   uint16  延时执行(秒), 0=立即
```

#### 开关应答 (0x09)

```
载荷：
  port    uint8   端口号
  result  uint8   0=成功, 其他=错误码
  state   uint8   执行后实际状态 0=关, 1=开
```

#### 读取/写入配置 (0x10/0x12)

```
载荷：
  条目数   uint8   1-10
  条目1:  key(uint8) | len(uint8) | value(len bytes)
  条目2:  ...
```

配置 Key 编码（同 v1.0）：

| Key | 名称 | 类型 | 说明 |
|-----|------|------|------|
| 0x01 | 上报间隔 | uint16 | 秒, 默认300 |
| 0x02 | 心跳间隔 | uint16 | 秒, 默认600 |
| 0x03 | 温度告警上限 | int16 | 0.1°C |
| 0x04 | 温度告警下限 | int16 | 0.1°C |
| 0x05 | 湿度告警上限 | uint8 | % |
| 0x06 | 水位告警下限 | uint16 | mm |
| 0x07 | 节点名称 | string | UTF-8, 最长32字节 |
| 0x08 | LoRa 发射功率 | uint8 | dBm, 默认13 |
| 0x09 | LoRa 扩频因子 | uint8 | 7-12, 默认9 |
| 0x0A | 传感器启用位图 | uint16 | |
| 0x0B | 状态上报间隔 | uint16 | 秒, 默认3600 |
| 0x0C | 数据缓存开关 | uint8 | 0=关, 1=开 |
| 0x0D-0x1F | **保留** | — | |
| 0x80-0xFF | **厂商自定义** | — | |

### 5.2 MAC 命令搭车 🆕

**借鉴 LoRaWAN 设计**：管理指令不单独发包，塞在数据帧载荷末尾。

```
Payload = [业务载荷(TLV)] + [MAC 命令区]

MAC 命令区格式：
  命令数 uint8 (0-5)
  CID(uint8) | Len(uint8) | Data(Len bytes) | ...
```

**当前支持的 MAC 命令**（每帧最多附带 5 条）：

| CID | 名称 | 方向 | 说明 |
|-----|------|------|------|
| 0x01 | LinkCheckReq | 上行 | 链路检查（同 0x1E，但搭车发送） |
| 0x02 | LinkADRAns | 上行 | 速率调整确认 |
| 0x03 | DutyCycleReq | 上行 | 占空比状态报告 |
| 0x04 | SensorCalibration | 下行 | 传感器校准指令 |
| 0x05 | SensorCalibrationAns | 上行 | 校准结果 |
| 0x06 | DeviceRestartReq | 下行 | 设备重启指令 |
| 0x07 | AlarmConfigReq | 下行 | 告警阈值即时更新 |
| 0x08 | BatteryStatusReq | 上行 | 电池状态详细报告 |
| 0x09 | TimeSyncReq | 下行 | 时间同步（含 UTC 时间戳） |
| 0x0A-0x1F | **保留** | — | |

**示例**：传感器数据帧末尾搭车 LinkCheckReq + BatteryStatusReq

```
Payload:
  [TLV: 温度 0x01|0x02|0x1F|0xFF]     ← 业务载荷
  [TLV: 湿度 0x02|0x01|0x41]
  [0x02]                              ← MAC 命令数=2
  [0x01|0x00]                         ← LinkCheckReq (CID=0x01, Len=0)
  [0x08|0x00]                         ← BatteryStatusReq (CID=0x08, Len=0)
```

### 5.3 紧急停止 (0x0E)

```
载荷：空
目标：0x0000 (广播)
Confirmed=1（必须应答）

行为：所有收到此帧的节点立即执行预定义的紧急动作（全关、全停、报警打开）

特殊处理：
  - 网关收到紧急停止指令 → 立即连续发送 3 次（三连发保证）
  - 节点收到紧急停止 → 立刻执行，不排队
  - 唯一可以打断其他指令的消息
  - ID=0xFFFF 保留给网关自身紧急指令
```

## 六、通信流程 (v1.1)

### 6.1 OTAA 入网（替换 v1.0 简单注册）

```
节点                              网关                          云服务器
 │                                 │                              │
 │ 上电/重启                        │                              │
 │ 读取 EEPROM: DevEUI, AppKey     │                              │
 │ 生成 DevNonce (随机2B)          │                              │
 │                                 │                              │
 │──(0x1A 入网请求)───────────────→│                              │
 │   DevEUI + DevNonce + JoinEUI   │── MQTT: join/request ──────→│
 │                                 │                              │
 │                                 │←── 验证 DevEUI 已注册 ──────│
 │                                 │   生成 AppNonce, DevAddr     │
 │                                 │   派生 NwkSKey, AppSKey      │
 │                                 │   (存于服务器侧)              │
 │                                 │                              │
 │←──(0x1B 入网确认)──────────────│                              │
 │   AppNonce+DevAddr+密钥材料     │                              │
 │                                 │                              │
 │ 派生 NwkSKey, AppSKey           │                              │
 │ 保存 DevAddr, 帧计数器=0         │                              │
 │                                 │                              │
 │──(0x18 心跳, DevAddr)─────────→│── MQTT: heartbeat ──────────→│
 │←──(0x19 心跳应答, 含UTC)───────│                              │
 │                                 │                              │
 │──(0x00 传感器数据)──→ 定时循环开始                               │
```

### 6.2 定时上报（正常循环）

```
节点 (每N分钟)                    网关                          云服务器
 │                                 │
 │ 读取传感器 → 打包TLV             │
 │ 检查是否有待发送MAC命令           │
 │                                 │
 │──(0x00 Unconfirmed)───────────→│── MQTT→ PostgreSQL
 │   [TLV传感器数据][MAC cmd区]     │
 │                                 │
 │ (每小时一次)                     │
 │──(0x01 Unconfirmed, 设备状态)──→│── MQTT→ PostgreSQL
 │                                 │
 │ (每10分钟)                       │
 │──(0x18 Unconfirmed, 心跳)──────→│
 │←──(0x19 Unconfirmed, 心跳应答)──│  含UTC时间(校时)
 │                                 │
 │ (每30次上报)                     │
 │ 附带 MAC LinkCheckReq           │
 │←── MAC LinkCheckAns (搭车返回)   │
```

### 6.3 下行指令（Confirmed，有确认+重试）

```
云服务器                          网关                           节点
 │                                 │                              │
 │── MQTT: device/{id}/cmd ──────→│                              │
 │                                 │──(0x08 Confirmed, seq=N)───→│
 │                                 │   5秒超时计时器启动           │
 │                                 │                              │ 执行
 │                                 │←──(0x09 Confirmed, seq=N)───│
 │←── MQTT: device/{id}/ack ──────│                              │
 │                                 │                              │
 ⚠ 超时5秒未收到ACK → 重发（相同seq），最多3次
   3次失败 → MQTT发布 device/{id}/offline + 告警通知
```

### 6.4 ADR 循环

```
节点                              网关                           
 │                                 │
 │ 初始: DR3(SF9), TX=14dBm       │
 │                                 │
 │──(0x00 Unconfirmed)──→ 20包 ──→│ 收集 RSSI/SNR 统计
 │  ... ×20                       │
 │                                 │ 评估：RSSI均值 -55dBm
 │←──(0x1C Confirmed, ADRReq)────│ 建议: DR5(SF7), TX=10dBm
 │      DataRate=5, TX=10dBm      │
 │                                 │
 │ 应用新速率                       │
 │──(0x1D Unconfirmed, ADRAns)───→│ OK
 │                                 │
 │ 之后以 SF7 发包（快50倍省电）    │
 │──(0x00 Unconfirmed, SF7)──────→│
 │                                 │
 │ ⚠ 若连续3次LinkCheck显示丢包     │
 │   节点自动降一级 → SF8           │
```

### 6.5 紧急停止（无确认等待，广播三连发）

```
云服务器                          网关                          所有节点
 │                                 │                              │
 │── MQTT: emergency_stop ───────→│                              │
 │                                 │──(0x0E 广播 0x0000)────────→│ 立即执行
 │                                 │──(0x0E 广播 0x0000)────────→│ 再发
 │                                 │──(0x0E 广播 0x0000)────────→│ 三连发
 │                                 │                              │
 │                                 │←──(0x0F Confirmed) ────────│ 各节点逐一应答
 │←── MQTT: emergency_stop/ack ───│  汇总: 35/35 节点已响应       │
```

## 七、跳频方案 🆕

SX1278 虽单通道，但节点可以跳频——避免 100 个节点同时挤一个频率。

### 信道计划（433MHz ISM）

```
CH0=433.175MHz  CH1=433.375MHz  CH2=433.575MHz  CH3=433.775MHz
CH4=433.975MHz  CH5=434.175MHz  CH6=434.375MHz  CH7=434.575MHz

默认信道：CH4 (433.975MHz)
入网信道：CH4（节点首次入网在此信道发送 Join-Request）
```

### 跳频策略

```
节点行为：
  每次上报随机选择 8 个信道之一
  入网请求固定在 CH4
  ADR 指令可调整信道掩码（ChMask），通知节点可用信道集合

网关行为：
  单通道轮询：每 200ms 切换一个信道
  8 信道循环周期 ≈ 1.6 秒
  收到前导码 → 锁定当前信道 → 接收完整包 → 继续轮询

100 节点 × 每小时 1 包 = 1.7 包/分钟
8 信道 × 轮询 → 每个信道每分钟约 1.7/8 ≈ 0.2 包
碰撞概率极低。
```

## 八、占空比限制 🆕

中国 433MHz ISM 频段规定：发射占空比 ≤ 1%。

### 固件侧检查

```
每包空中时间估算：
  SF7:  16字节 ≈ 51ms
  SF9:  16字节 ≈ 205ms
  SF12: 16字节 ≈ 1.5s

占空比检查逻辑（节点固件）：
  记录最近 1 小时发射总时长
  发射前检查：(本次包时长 + 最近1h累计) / 3600s ≤ 1%
  
  例：SF7下每小时最多发 3600*0.01/0.051 ≈ 705 包 → 远超需求
      SF12下每小时最多发 3600*0.01/1.5 ≈ 24 包   → 勉强够用
  
  ADR 自动处理：若节点处于 SF12 且上报间隔 < 150s，
  占空比可能违规 → 自动触发 LinkCheck 评估是否需要降 SF。
```

**结论**：默认 SF9 + 300s 间隔，占空比仅 0.02%，完全合规。

## 九、帧计数器与防重放 🆕

### 规则

```
节点侧：
  - 帧计数器 8bit，存在 EEPROM（掉电不丢）
  - 每发一包递增（0→1→2→...→255→0 回绕）
  - 回绕时触发重入网流程 (0x1A)
  - 入网成功后帧计数器从 0 开始

服务器侧：
  - 记录每个节点最后一次收到的帧计数器
  - 新包帧计数器 ≤ 上次记录 → 静默丢弃（重放攻击/重复包）
  - 帧计数器跳变（如突然从 50 跳到 200）→ 标记节点可能重启，等待重入网
```

### 上下行独立计数

```
上行帧计数器：节点维护，存在节点 EEPROM
下行帧计数器：云端维护，存在数据库

两者独立，互不影响。
```

## 十、版本兼容策略

- 协议版本在 Byte0 高 2bit
- 接收方检查版本：同版本正常处理；旧版本按旧格式解析；新版本（比自己高）→ 尝试解析已知字段，忽略未知字段
- 关键修改原则：
  - 新增消息类型：向后兼容，老节点不认识就忽略
  - 新增 TLV 字段：老节点跳过不认识的 Type
  - 修改现有字段含义：必须升主版本号（1.x → 2.0）
  - 帧头结构变更：必须升主版本号（如本次 v1.0→v1.1，帧头增加了 1 字节帧计数器，应升主版本为 v2.0，但为了渐进升级保留 1.x）

### v1.0 → v1.1 兼容性

> ⚠️ v1.1 帧头 7 字节，v1.0 帧头 6 字节，**不兼容**。
> 所有节点固件需升级到 v1.1。首次部署即使用 v1.1，无历史包袱。

## 附录：与 LoRaWAN 的关系

本协议是**吸收 LoRaWAN 精华的私有 LoRa 协议**。选择私有协议 + 借鉴 LoRaWAN 的原因：

| 对比维度 | 私有协议 v1.1 | 完整 LoRaWAN |
|----------|--------------|-------------|
| 网关 | 自建 ESP32+SX1278 ¥95 | LoRaWAN 网关 ¥450+ |
| 入网 | OTAA 密钥派生 ✅ | OTAA / ABP |
| 自适应速率 | ADR ✅ | ADR ✅ |
| 帧计数器防重放 | ✅ | ✅ |
| 下行控制 | 随时可发，不受 Class 限制 | Class A 仅上行后短暂窗口 |
| MAC 命令搭车 | ✅ | ✅ |
| 跳频 | ✅ 8信道 | 8-64信道 |
| 占空比 | ✅ 固件检查 | 网络服务器强制 |
| 扩展性 | 完全自定义 | 标准协议，受限 |
| 成本 | 极低 | 中等 |
